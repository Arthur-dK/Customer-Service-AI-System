# ADR 022: Privacy — in-memory caller audio, log redaction, no TwiML Record

## Context
The IVR must not record calls or persist utterance audio. PIN strings and full phone numbers must not appear in logs. Canned TTS phrase-cache `.mulaw` and Hugging Face model files may remain on disk. `last4_phone` already exists on the shared card store (ADR-020).

## Decision
- Caller PCM/μ-law lives only in process memory (VAD/STT buffers) and is discarded after `finish()`.
- Application logs print `from_last4` via `last4_phone`, never transcripts, PINs, or full E.164. Media Stream `start` must not dump `customParameters` (it contains `from`).
- Placeholder turn logs include phrase id and TTFB, not transcript text. `TurnResult.transcript` stays in memory for tests only.
- Voice webhook TwiML is `<Connect><Stream>` only — no `<Record>` and no recording callback.
- Pytest after a simulated turn: fail if `.wav`/`.mp3` appeared under a temp dir, or if caplog contains a fixture full number or a planted PIN.
- Manual verifiers that write wav stay under gitignored `scratch/` and are not on the live call path.

## Trade-off Analysis
- **Benefit:** Automated regression for the “zero recording” rule; last-4 is still enough to debug which allowlisted caller rang.
- **Drawback:** Twilio account-level recording (console) is outside this app; operators must leave it off. TwiML still passes `From` to the stream as a parameter (needed for identity); that is signaling, not a recording or a log line.
