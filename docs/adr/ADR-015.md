# ADR 015: Placeholder turn engine (templated intents)

## Context
Language selection already picks a language once. The next IVR slice must answer after the caller stops talking, within ~500 ms for canned lines, without an LLM or live card systems. STT, phrase cache, streaming TTS, and TTFB exist but were not composed.

## Decision
- Add `PlaceholderTurnEngine` (`services/ivr/turn_engine.py`): `speech_end` → stub transcript → `map_placeholder_intent` → `stream_ready_phrase` → `enqueue_tts_stream` (first chunk stops TTFB).
- Intents are keyword maps onto catalog IDs: fake balance, PIN, block, goodbye, or “did not catch that.” No card APIs and no generated sentences.
- Opening `main_menu` playback does **not** start the TTFB clock. Only replies after `speech_end` do.
- Language is an engine constructor argument (already known). Do not run LID per turn.
- Live Twilio wiring waits for Phase 6. This phase is proven with stubs and a median canned TTFB ≤ 500 ms test.

## Trade-off Analysis
- **Benefit:** The 0.5 s path is exercisable offline; later real STT/TTS/card backends slot in without changing the turn shape.
- **Drawback:** Keyword routing is brittle; unknown phrasing always gets the error prompt. That is acceptable until a constrained intent model exists.
