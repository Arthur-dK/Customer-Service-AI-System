# ADR 023: faster-whisper on selected language, thread offload

## Context
SAPI grammars and scripted STT cannot feed paraphrases or Hebrew/Arabic into the embedder. A paid streaming vendor is out of scope. Language ID already ran at call start (FEAT-02). Caller audio must not be written to disk (ADR-022).

## Decision
- Implement `WhisperStreamingSpeechToText` (`services/ivr/whisper_stt.py`) on the existing `StreamingSpeechToText` protocol.
- `start(language=)` stores the **already selected** call language (normalized ISO 639-1) and passes it into faster-whisper. Do not add a new LID module or per-turn language ID.
- Buffer μ-law until VAD `speech_end`, then `asyncio.to_thread` for CPU transcription; drop the buffer afterwards. Never write `.wav`/`.mp3`.
- Default size `base` (`IVR_WHISPER_MODEL`). pytest injects `transcribe_fn`; `IVR_STT_BACKEND=scripted` remains the CI default.
- Warm the model at process start when the whisper backend is selected (may be slow). Rare >2 s transcripts are acceptable; frequent slowness is not.
- Logs: language, byte count, `stt_ms` — not transcript text.

## Trade-off Analysis
- **Benefit:** Full-sentence multilingual STT without a new language detector; event loop stays free for Twilio frames.
- **Drawback:** Batch (not streaming) STT; TTFB includes recognition time; RAM on Render grows. `faster-whisper` is optional until demo/Render install it.
