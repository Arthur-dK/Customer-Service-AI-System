# ADR 021: BGE-M3 prototype router

## Context
Keyword maps (ADR-015) miss paraphrases and Hebrew/Arabic. FEAT-04 needs a local semantic router onto a closed card-action set, without an LLM on the call path. The same actions will later be requested over SMS and Email, so the router is not an IVR-only module.

## Decision
- Target actions: `get_balance`, `get_pin`, `get_card`, `get_card_statement`, `block_card`, `unblock_card`. Goodbye is not a target.
- Store two example phrases per action per `en`/`he`/`ar` in `core/intents/prototypes.json`. Embed them once at warmup.
- Classify with cosine similarity to the nearest prototype per action. Reject when the top score is below a minimum **or** the gap between top-1 and top-2 is below a margin (two plausible actions).
- Production embedder: in-process `BAAI/bge-m3` (`sentence-transformers`), selected with `INTENT_EMBEDDER=bge`. Pytest: `HashTokenEmbedder` (no download). Optional `@slow` test for the real model.
- No keyword fast-path. If classify regularly exceeds ~3 s, shrink the prototype set or swap to a smaller multilingual model.

## Trade-off Analysis
- **Benefit:** Same vector space for EN/HE/AR; CI stays offline; IVR/SMS/Email can share `core.intents`.
- **Drawback:** CPU RAM and first-load time for BGE-M3; hash embedder quality is only a stand-in for pytest.
