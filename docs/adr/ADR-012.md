# ADR 012: Phrase IDs and ready audio buffers

## Context
Menus, errors, and placeholder task lines play often. Synthesizing them on every turn (especially Windows SAPI) blows the 500 ms TTFB budget. Hashing raw text (ADR-005 `.cache/ivr-tts`) works, but copy edits change the hash and look like a cache miss. Dynamic DTMF menus still depend on the caller’s country shortlist, so they are not a single static line.

## Decision
- Keep a catalog of **stable phrase IDs** in `core/language/phrases.json` (id → language → text).
- `PhraseAudioCache` stores 8 kHz μ-law in memory (optional disk `.cache/ivr-phrases/{id}.{lang}.mulaw`).
- The latency-critical path uses **`get_ready`** only (dict lookup, no TTS). Fill via **`warmup`** at process start or **`get`** on first use.
- This branch warms **English + French** (catalog `warmup_languages`). Skip languages the TTS backend cannot speak.
- Dynamic DTMF language menus stay on existing text TTS + ADR-005 cache until a later phase pre-renders per locale.

## Trade-off Analysis
- **Benefit:** TTFB for canned lines does not include synthesis; IDs stay stable when we only tweak unused languages; easy to add voices later.
- **Drawback:** New copy requires warmup before it can play on the hot path; country-specific keypad menus are still generated text.
