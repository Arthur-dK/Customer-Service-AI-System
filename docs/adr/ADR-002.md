# ADR 002: Stream-native language selection (not TwiML Gather)

## Context
Callers must choose a language by speaking or by keypad before the rest of the IVR continues. Twilio offers `<Gather>` / `<Say>` for simple menus, but that path cannot run custom VAD, SpeechBrain LID, barge-in over our own TTS buffer, or queue-based testing with a fake media stream.

## Decision
Run language selection entirely on the Twilio Media Stream WebSocket: inbound μ-law frames and DTMF events feed `asyncio.Queue`s; `LanguageSelector` in `services/ivr/language_selection.py` owns prompt → listen → DTMF-menu → done. Incoming Voice webhook only returns TwiML that starts the bidirectional stream (`services/ivr/twiml.py` + `app/api/ivr.py`).

## Trade-off Analysis
- **Benefit:** One pipeline for speech LID, DTMF, barge-in, metrics, and offline harnesses; no round-trip through Gather callbacks.
- **Drawback:** We own playback timing, barge-in clear, and silence timeouts ourselves instead of relying on Twilio’s built-in Gather UX.
