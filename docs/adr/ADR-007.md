# ADR 007: DTMF fallback with speech barge-in

## Context
Speech LID will not always succeed (silence, noise, low confidence). Callers still need a reliable way to pick a language. During the DTMF menu they may start speaking instead of pressing a key.

## Decision
After silence timeouts, enter a DTMF menu built from the caller’s locale languages (`build_dtmf_menu_prompt` / digit mapping). While the menu plays or waits, accept:
- valid DTMF digits → select that language and clear playback;
- speech barge-in → run LID on the captured utterance (`speech_barge_in`).

Invalid digits are ignored; repeated menu rounds are capped (`max_dtmf_rounds`).

## Trade-off Analysis
- **Benefit:** Accessibility and reliability when LID fails; barge-in preserves “just speak” UX during the menu.
- **Drawback:** Menu audio can contaminate the mic until `clear` runs; barge-in LID is harder than post-prompt quiet listening.
