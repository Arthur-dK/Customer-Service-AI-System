# ADR 017: Live smoke for canned TTFB (scripted STT)

## Context
Phases 1–6 prove the pipeline offline. A real call is needed to confirm prompts and canned replies are audible and feel quick. The STT stub still cannot recognize speech. The official 500 ms clock is in-process TTFB, not handset delay.

## Decision
- Live smoke is documented in `docs/features/FEAT-03.md` Phase 7. Readiness: `manual_verify_smoke.py --phase 7`.
- `IVR_STT_SCRIPT` (comma-separated) queues stub transcripts so a handset call can play fake balance / PIN / goodbye without a paid STT. Empty script → “did not catch that” after each utterance (still a canned-line TTFB check).
- Log `placeholder_turn … ttfb_ms=…` on each reply. That is the SLO. Hearing a snappy start on the phone is a sanity check only.
- Test English first. French catalog lines exist; spoken French TTS needs Piper (or similar). Windows SAPI is English-capable.
- Do not store call audio.

## Trade-off Analysis
- **Benefit:** A real phone can exercise language select → menu → canned reply without waiting for Deepgram.
- **Drawback:** What you say is ignored until a real STT backend is plugged into `StreamingSpeechToText`. Ear-to-ear latency includes Twilio and is not the pass/fail metric.
