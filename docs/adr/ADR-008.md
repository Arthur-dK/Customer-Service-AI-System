# ADR 008: Caller locale from phone country data

## Context
DTMF menus and prompt language should reflect where the caller is dialing from (e.g. GB vs IL), without hard-coding one global language list in the selector.

## Decision
Resolve locale from the inbound `From` number via `core/language` country tables (`country_languages.json`, calling codes). `CallerLocale` carries `languages`, `prompt_language`, and whether the country was known. Unknown numbers fall back to a default English-oriented prompt set.

## Trade-off Analysis
- **Benefit:** Country-appropriate menus (e.g. GB: en/pl/pa/ur/bn) and prompt language without per-call config.
- **Drawback:** Phone country ≠ preferred language; travelers and VoIP numbers may get the wrong menu defaults — speech LID / barge-in still allow other languages when the model is confident.
