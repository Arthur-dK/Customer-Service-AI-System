# ADR 003: Twilio 8 kHz μ-law as the IVR audio contract

## Context
Twilio Media Streams deliver and expect 8 kHz mono μ-law. Downstream LID (SpeechBrain) expects 16 kHz PCM. The stack needed a single conversion layer shared by VAD, TTS, tests, and the live WebSocket.

## Decision
Treat 8 kHz μ-law as the wire format everywhere on the media stream. Central helpers live in `services/ivr/audio.py` (`mulaw_to_pcm16`, `pcm16_to_mulaw`, resample, chunking, tone generation). SpeechBrain LID resamples 8 kHz PCM → 16 kHz only at the classifier boundary.

## Trade-off Analysis
- **Benefit:** Matches Twilio exactly; unit tests and the fake harness use the same bytes the phone hears.
- **Drawback:** Telephony bandwidth limits accent/detail for LID; short noisy utterances are inherently harder than studio audio.
