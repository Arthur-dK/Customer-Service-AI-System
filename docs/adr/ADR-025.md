# ADR 025: HE/AR catalog + Edge TTS warmup

## Context
FEAT-04 callers choose Hebrew or Arabic at the start of the call (FEAT-02). Phase 5 dialogue IDs existed mainly in English. Windows SAPI often has no Hebrew/Arabic voice; a local Piper model per language is out of scope. Static lines must still hit the warmed μ-law cache (~500 ms). Slot templates (`{last4}`, `{balance_text}`) cannot be pre-rendered.

## Decision
- Catalog every FEAT-04 phrase id in `en`, `he`, and `ar` (`core/language/phrases.json`). Keep French on FEAT-03 placeholder IDs. Default `warmup_languages` is `en` / `he` / `ar`.
- PIN copy is SMS-only in every language: no digit characters and no spoken PIN digits. `placeholder_pin` matches that rule so the old keyword engine cannot read a PIN aloud.
- Phrase-cache warmup skips lines whose catalog text contains `{`. Edge TTS (`he-IL-HilaNeural`, `ar-SA-ZariyahNeural`) is the Linux/Render voice for Hebrew and Arabic when the package is installed. Pytest does not call the network; it asserts `supports_language` and catalog text.
- If Edge/SAPI/Piper cannot speak `he` or `ar`, play English audio of English text (ADR-018), not an English-accented rendering of Hebrew/Arabic script.

## Trade-off Analysis
- **Benefit:** Hebrew and Arabic callers hear matching catalog copy after language select; PIN digits never appear in spoken strings; boot still warms only static lines.
- **Drawback:** Slot replies still synthesize on the turn. Edge needs outbound HTTPS. Stub `balance_text` / `statement` / `status` interpolated from the store may remain English.
