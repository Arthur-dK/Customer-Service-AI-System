# ADR 014: Streaming STT protocol with local VAD utterance bounds

## Context
After language is known, the IVR must turn caller speech into text so templated replies can play. Cloud STT (Deepgram) and local models (Whisper-class) differ in APIs, but TTFB still starts when the **caller stops talking**. Energy VAD already emits `speech_end`. We must not store call audio.

## Decision
- Add `StreamingSpeechToText` in `services/ivr/streaming_stt.py`: `start(language)` → `feed_mulaw` → `finish` on VAD `speech_end` → `aclose`.
- **Do not run language ID on every sentence.** `start` receives the language already chosen.
- **Utterance end stays local** (ADR-004 `EnergyVad`). Vendor endpointing can be added later; it must not replace the TTFB start marker for this feature.
- **Free stub:** `ScriptedStreamingSpeechToText` ignores audio and returns queued phrases (for CI and placeholder tasks). No network.
- **Swap path:** Deepgram or an on-machine model implements the same protocol. Do not persist μ-law or transcripts to disk.
- `feed_until_speech_end` is the offline helper: chunk audio → VAD → `mark_speech_end` → `finish`.

## Trade-off Analysis
- **Benefit:** Tests never need API keys; paid/private STT is a constructor change; TTFB start stays aligned with “person stopped talking.”
- **Drawback:** The stub cannot recognize real speech. Live quality depends on a later backend. Interims are optional and unused until barge-in needs them.
