# ADR 010: Offline harness before live Twilio smoke

## Context
Live phone + ngrok iterations are slow and expensive for debugging audio framing, VAD, TTS, and selection state. The team needed confidence before Phase 9/10 handset tests.

## Decision
Build in this order: μ-law helpers → VAD → TTS → Fixed LID → `LanguageSelector` → fake Twilio media-stream harness (`tests/ivr/manual/fake_twilio_stream.py`) → TwiML/webhook unit tests → Phase 9 fixed-LID live smoke → Phase 10 SpeechBrain live speech. Keep pytest under `tests/ivr/pytest/` and manual verifiers under `tests/ivr/manual/`. Document the full process and smoke profiles in `docs/features/FEAT-02.md`.

## Trade-off Analysis
- **Benefit:** Most regressions caught offline; live calls validate only what cannot be faked (handset speech, Twilio buffer/clear).
- **Drawback:** Fake harness cannot fully reproduce acoustic echo or network jitter; some bugs only appear on the phone (playback choppiness, barge-in bleed).
